# 表格与数据规则

只要需求会输出或依赖业务表格、报表、台账、看板表格或导出文件，就应用本参考规则。

将表格定义写为 `三、目标` 下的子章节，并在 `五、当前阶段验收标准` 中体现相应检查。不要新增核心章节。

## 必须定义的内容

### 用途与粒度

- 说明该表格支持的决策或任务。
- 定义结果中的一行代表什么。
- 区分源记录和完整业务对象。除非已确认二者是一一对应关系，否则绝不能把文件行数当作业务对象数量。

### 结构

- 定义字段及其业务含义。
- 定义分组、排序、小计行和总计行。
- 适用时，标明可编辑字段、派生字段和标识字段。

### 来源与上下文

- 明确权威来源系统、报表/数据集和源字段。
- 确认主体、账户、部门或其他权属范围。
- 确认起止时间边界，以及源数据的生成/导出/刷新时间。
- 除非用户要求，否则不要扩展为如何采集缺失元数据的技术设计。

### 取数与转换

- 定义时间范围、状态范围、筛选条件、刷新时点、关联关系和匹配键。
- 明确定义分类映射；来源标签与结果标签不必相同。
- 定义求和、计数、去重、分组、比例、正负号和舍入规则。
- 适用时，定义空值、重复、冲正、退款、取消、跨期和无法匹配数据的处理方式。

### 勾稽与核对

- 定义可重复计算的等式，将源明细、转换后明细、汇总总额和余额连接起来。
- 定义容差，以及超过容差时的处理方式。
- 只有在当前需求已经确认该行为时，才可在数据不完整或不一致时停止生成输出。

## 转换规则表

对于明细汇总或分类需求，使用映射表：

| 来源类型 | 方向/状态 | 结果类型 | 纳入规则 | 金额/正负号规则 | 去重键 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 类型 A | 收入 | 类别 1 | 已确认记录 | 正数 | 业务 ID + 行 ID | 模拟示例 |
| 类型 B | 支出 | 类别 2 | 成功记录 | 负数 | 会计分录行 ID | 模拟示例 |
| 类型 C 冲正 | 收入 | 类别 2 | 仅纳入已关联的冲正记录 | 正数 | 原记录 ID + 冲正记录 ID | 冲销类型 B |

本示例有意展示多个来源类型可能映射到同一个结果类型。不要把这些规则复制到真实需求中；每一行都必须替换为有来源支撑或经用户确认的映射。

## 勾稽示例

使用有名称的业务术语，不要使用含义不明的固定数字：

```text
净变动额 = 收入明细合计 + 支出明细合计
期末余额 = 期初余额 + 净变动额
汇总类别总额 = 该类别下映射后明细金额的合计
勾稽差额 = 报表总额 - 重新计算总额
当勾稽差额的绝对值 <= 已确认容差时通过
```

## 表格完成检查

- 行粒度清晰无歧义。
- 已明确来源系统、字段、权属范围和时间范围。
- 使用关联、筛选、映射、聚合、正负号和去重规则时，均已明确说明。
- 明细数量没有与业务对象数量混淆。
- 总额能够通过已记录的等式完成勾稽核对。
- 未知规则已标记为待确认，而不是自行推断。
