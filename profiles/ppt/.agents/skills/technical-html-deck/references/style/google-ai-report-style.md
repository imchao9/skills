# Google AI Responsibility Report Style Reference

Reference artifact:

- `https://ai.google/static/documents/ai-responsibility-update-2026.pdf`
- Local visual sample: `/Users/cm/Documents/me/skills/debug/references/google-ai-responsibility-2026/png/`

Use this as a reference for external-facing reports and promotional HTML pages, not as a direct template.

## What To Borrow

1. White-space confidence
   - Use large white margins and let one dominant visual or headline carry the page.
   - Avoid filling every row with cards.

2. Keyword color emphasis
   - Keep most headline text black.
   - Color only the decisive phrase or topic word.
   - For CM style, use teal/blue/green/amber/rose instead of Google brand colors.

3. Modular rounded image system
   - Use large rounded image panels.
   - Repeat one visual motif with different crops when building a cover or product reveal.
   - For CM style, prefer real product screenshots, generated artifact screenshots, or domain-specific visuals over generic abstract art.

4. Report-like case study layout
   - Strong title and short thesis on the left.
   - Large proof visual on the right or lower right.
   - Supporting evidence in short columns or quote blocks.
   - Use this for external promo pages and high-level internal case sections.

5. Simple footer discipline
   - A quiet footer line, brand/project name, and page number can make long-form output feel finished.

## What Not To Borrow Directly

- Do not copy Google branding, logo placement, exact colors, icon style, or visual assets.
- Do not copy the A3 page ratio into 16:9 decks.
- Do not copy the high text density into presentation slides.
- Do not use abstract AI art when the user needs to inspect an actual product, architecture, or output.
- Do not make internal technical review decks feel like corporate annual reports unless the user asks for a report artifact.

## CM Adaptation

For external promotional HTML:

- First viewport: left headline + right real artifact/product screenshot, optionally with slight perspective.
- Proof section: one strong screenshot or diagram, plus 3 concise claims.
- Case section: left thesis + right large image/screenshot + bottom quote or metric.
- CTA: explicit next action, not a generic closing paragraph.

For internal technical review:

- Borrow the big concept diagram pattern, not the long prose.
- Use one large diagram plus side notes.
- Keep review-specific sections: decision asks, MVP boundary, acceptance gates, risks.

## Prompt Hint

When applying this reference, say:

> Use Google AI report-inspired restraint: white canvas, large headline, selective keyword color, one dominant rounded proof visual, and sparse evidence blocks. Do not copy Google branding or long report text density.
