# TAPD

基于已核实的命令或工具契约操作 TAPD。优先使用紧凑、机器可读的结果，保护凭证，
并把创建、更新、关联、评论、工时、Wiki、测试用例和消息发送统一视为外部写操作。

## 选择执行方式

1. 检查是否已经安装 `tapd`：

   ```bash
   command -v tapd
   tapd --help
   ```

2. 已安装时优先使用 `tapd-ai-cli`。以当前 `--help` 输出作为命令契约，不要依赖记忆中的参数。
3. CLI 不可用时，检查当前已连接 TAPD MCP 暴露的真实工具。只使用现场可见的工具名和 Schema。
4. CLI 和 MCP 都没有可用认证、但用户提供了 TAPD URL 时，使用可用的浏览器控制 skill
   复用用户现有登录态。打开准确 URL，只读取页面或已观察到的响应数据。不要读取 Cookie、
   Local Storage、密码、令牌或浏览器会话文件。
5. 所有方式都无法读取时，说明缺少的依赖或登录状态，并按需读取
   [后端说明](references/backends.md)。未经用户授权，不要安装 CLI、启动 MCP 或索取凭证。

除非有明确理由，不要在同一次操作里混用 CLI 和 MCP 的结果。记录结果来自哪种执行方式。

配置或测试凭证前先读取[认证说明](references/authentication.md)。TAPD 个人访问令牌是通过
`TAPD_ACCESS_TOKEN` 提供的 Bearer 凭证，不是 AK/SK。不要把真实令牌写进此 skill、
示例、命令参数或 Git 跟踪文件。

## 确定对象和范围

- 把用户提供的 TAPD URL 作为权威输入。详情 URL 优先执行 `tapd url '<tapd-url>'`，
  在不持久化工作区选择的情况下解析项目和条目。列表或视图 URL 先解析工作区，同时保留
  完整 URL，因为 CLI 可能无法复现保存视图。
- 对列表 URL，保留 `categoryId`、`sort_name`、`order`、`conf_id`、
  `useScene` 等全部参数。`conf_id` 可能代表无法仅由可见 URL 参数还原的视图范围；
  CLI 或 MCP 无法复现时，以准确的登录后页面为准。
- 使用 `tapd workspace list` 发现项目。
- 单次查询优先使用 `--workspace-id <id>`。只有用户明确要求修改当前目录的
  `.tapd.json` 时，才执行 `tapd workspace switch <id>`。
- 区分需求、任务、缺陷、迭代、Wiki、测试用例、发布计划和工时 ID。上下文不足时，
  不要根据裸数字 ID 猜测条目类型。
- 先通过 `tapd workspace list` 等无副作用读取验证认证，再确认目标工作区权限。
  不要输出访问令牌、API 密码、应用密钥、Basic Header、MCP 环境变量块或
  `.tapd.json` 内容。

CLI 的凭证优先级是：命令参数、环境变量、当前目录 `./.tapd.json`、用户目录
`~/.tapd.json`。优先使用安全注入的 `TAPD_ACCESS_TOKEN` 或现有认证配置，
不要为了方便而持久化凭证。

## 操作前检查

1. 读取对应的现场命令契约：

   ```bash
   tapd --help
   tapd story list --help
   tapd story show --help
   ```

2. 确定准确的工作区、条目类型、条目 ID 和所需字段。
3. 涉及流程或字段的操作，先读取工作区当前的字段、状态、工作项类型和流转元数据。
   不要编造字段键、自定义字段名、状态值、处理人标识或目标流转状态。
4. 使用能够回答问题的最小查询。结果可能超过一页时完成分页，并说明限制或截断情况。

常用查询、筛选、状态汇报、URL 解析和写操作准备见[操作示例](references/recipes.md)。

## 查询与汇报

- 列表查询优先使用 CLI 默认的紧凑 JSON。
- 详情命令默认输出精简 Markdown。只有需要确定性提取字段时才加 `--json`；
  Agent 处理时不要使用 `--pretty`。
- 可复用筛选条件使用一个或多个 `--filter 'field=OP<value>'`。使用自定义字段前先确认字段名。
- 未经当前 CLI 版本验证，不要相信过滤列表中的 `total` 和 `has_more`。已审计版本会通过
  独立 count 请求计算这些字段，可能忽略分类、处理人、迭代、标签、名称、自定义字段等过滤条件。
  应按实际返回的 `items` 数量分页：当前页达到 `limit` 时继续，少于 `limit` 时停止。
- 状态汇报分别计算需求、缺陷和任务数量，再读取相关迭代。说明工作区、筛选条件、生成时间、
  分页覆盖和不可用部分。
- 区分 TAPD 事实和解释。保留条目 ID 与 URL，便于核验。
- 只读取了一页或过滤子集时，不要声称完成了全工作区扫描。
- 浏览器读取时，记录视图名、可见筛选条件、总数、表头、排序方向、已渲染行数和分页覆盖。
  总数大于当前行数时，通过可见分页控件继续读取，不要编造查询令牌或 URL 变体。

## 严格控制写操作

只有用户当前请求明确授权了具体外部变更时，才执行 TAPD 写操作。方案、示例、审查、
诊断或含糊表述都不构成写入授权。

写入前：

1. 读取当前记录和目标命令或 MCP Schema。
2. 确认权威字段和允许的流程流转。
3. 工作区、条目、修改字段或目标值仍有歧义时，先明确复述并确认。
4. 优先单条修改，不要用批量更新或创建关联作为快捷方式。

写入后：

1. 检查退出状态或结构化成功结果。
2. 通过只读操作重新读取被修改的记录。
3. 汇报已验证字段、ID、URL 和服务端归一化后的值。

以下操作即使不修改主条目，也统一视为写操作：

- 新增或更新评论。
- 填写或更新工时。
- 创建或修改关联关系。
- 上传附件或图片。
- 创建或更新 Wiki 页面或测试用例。
- 发送企微机器人消息。
- 持久化工作区或认证配置。

不要把密钥插入可能回显到日志的命令字符串。使用安全注入的环境变量或交互式隐藏输入，
并在读取完成后清除任务级令牌。用户在聊天中粘贴令牌时，只有获得明确授权后才使用，
并建议验证后撤销或轮换。

## MCP 约束

官方 TAPD MCP 不是只读工具。已审计实现包含需求、任务、缺陷、评论、迭代、关联、
测试用例、Wiki、工时和企微消息的创建或更新能力。

- 每次调用陌生工具前检查现场 MCP Schema。
- 把以 `create`、`update`、`add`、`entity_relations`、`send` 开头或语义等价的工具视为写操作。
- 不要因为 MCP 工具只接收通用 `options` 对象就认定它安全。
- MCP 语义不清楚时，优先使用 CLI 读取。

## 浏览器约束

- 只有用户提供 TAPD URL 或已明确定位 TAPD 页面，且 CLI/MCP 能力检查失败时，才使用浏览器兜底。
- 复用现有登录态，不要读取或导出 Cookie、存储数据或凭证。
- 优先打开准确 URL，并进行有界的 DOM 或表格提取，不要抓取无关工作区内容。
- 创建、编辑、保存、持久化筛选、保存视图、批量选择、导出、下载附件和发送消息都属于副作用；
  只读请求期间不要点击这些操作。
- 在结果中保留长短 ID、筛选条件、排序和分页覆盖，确保可审计。

## 失败处理

- 认证失败：说明缺少的认证方式，不要暴露凭证值，也不要静默切换认证方式。
- 工作区不存在：先发现或询问工作区，不要猜测。
- 字段或状态未知：读取当前元数据，不要用编造值反复尝试。
- 返回空数据：区分真实空结果与权限、分页、筛选或工作区错误。
- 限流或临时网络错误：保留原始请求，只在安全时重试；写操作结果未确认前不要重放。
- 部分汇报：返回已经核实的部分，并明确受阻部分。

## 交付结果

先给结论，再说明工作区和条目范围、执行方式、读写分类、已验证的 ID 或 URL、
筛选与分页情况以及剩余不确定性。不要包含凭证值或原始私密响应。
