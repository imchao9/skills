# 教学加工契约

> 来源：`teach/SKILL.md`、`teach/MISSION-FORMAT.md` 与已批准的 `codemao-learning` 设计。用途：作为每个微型 lesson 的教学目标、读者适配、知识边界、资料呈现和已批准裁剪的单一事实源。

## Mission 与默认读者

Mission 必须原样使用：

> 让团队开发人员快速理解真实开发过程中产生的非显然技术经验，并能够在相似任务中正确识别、判断和应用这些经验。

默认读者是当前项目的普通开发人员：掌握项目使用的语言、框架和基本开发流程，但不了解当前经验涉及的具体机制、设计取舍或排查技巧。

每个微型 lesson 都必须明确服务于 Mission，并落在默认读者的最近发展区：建立在其已有基础上，只补足完成当前迁移所需的新机制、判断或技巧。

## 教学范围与资料

每个微型 lesson 只教授取得一个具体、范围紧密的可观察收益所需的知识。内容应短小、可快速完成，但不设自定义字数或分钟上限。

资料呈现优先使用项目证据和高可信的一手资料。外部主张需要依据时，提供官方文档或其他首要来源；找不到足够来源时明确暴露缺口，不凭参数知识猜测。

## 已批准裁剪

以下规则是相对于 `teach` 默认工作流的明确偏离：

- 最终产物使用 Markdown，不生成 HTML lesson 或持续教学 workspace artifacts。
- 学习包允许承载多个微型 lesson；其数量与主题边界仅按 `resolution-contract.md` 的“主题与分类”执行，本契约不另行定义。
- 不强制加入练习、自检或反馈题。
- 用户指出不准确点后，直接依据用户反馈修改，不再次核验该反馈。

## 教学完成标准

每个主题仅在以下检查全部通过后完成：能指出一个具体且紧密限定的学习收益；该收益直接支持 Mission；内容适合默认读者的已有基础与最近发展区；只包含获得该收益所需的知识；项目证据与必要的一手来源已给出，或资料缺口已显式标注；内容短小且可快速完成；产物及交互遵守全部已批准裁剪。
