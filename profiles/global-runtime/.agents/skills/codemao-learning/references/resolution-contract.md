# 知识提取与学习包契约

> 来源：`ce-compound/SKILL.md`、`ce-compound/assets/resolution-template.md` 与已批准的 `codemao-learning` 设计。用途：作为资格判断、事实裁定、主题分类、正文结构和学习包格式的单一事实源。

## 资格与证据

生成草稿的必要条件是：存在至少一个高价值、可迁移且并非简单、显然或机械修改的主题。

另行评估“问题或任务是否已经解决”和“方案是否已经验证有效”。这两项是建议性成熟度信号，不是生成前提；任一信号缺失时不得仅因此停止生成，而要在草稿中明确当前状态、证据边界、候选结论和待验证事项。不得把尚未解决的问题描述成已解决，也不得把未经验证的方案描述成有效。

必要条件失败时，说明依据，不创建草稿。

事实裁定按以下优先级进行：

1. 当前对话用于还原推理过程与方案取舍。
2. 当前代码、Git diff、测试结果和项目文档用于确认技术事实。
3. 仅在必要时使用官方文档或其他一手外部资料补足机制依据。

不得把已放弃的提议写成最终建议；证据冲突或缺失时必须显式说明。问题未解决或方案未验证时，在对应章节中将其标记为当前判断或候选方案，并列出后续验证方式。

## 主题与分类

选择一至三个可迁移主题，并逐个独立分类：

- **Bug**：缺陷、失败或不符合预期的行为。
- **Knowledge**：实践、模式、决策或工作流指导。

一份 Markdown 是一个学习包；包内每个主题必须保持为独立的微型 lesson，不得把多个主题揉成一篇泛化总结。

## 正文结构

Bug 主题按以下中文标题及顺序组织：

1. `学习目标`
2. `前置知识`
3. `问题`
4. `问题表现`
5. `未奏效的尝试`
6. `解决方案`
7. `为什么有效`
8. `预防措施`
9. `相关问题`
10. `首要参考资料`

Knowledge 主题按以下中文标题及顺序组织：

1. `学习目标`
2. `前置知识`
3. `背景`
4. `实践指导`
5. `为什么重要`
6. `适用场景`
7. `示例`
8. `相关内容`
9. `首要参考资料`

某章节在当前主题中属于可选且确实没有内容时，省略该章节；不得为填满结构而编造内容。保留的章节不得改名或改变相对顺序。

## Frontmatter 与命名

学习包只能使用以下 frontmatter 字段：

```yaml
---
title: 中文主题
date: yyyy-MM-dd
submitter: 提交人
topics:
  - 中文技术主题一
---
```

- `title`：具体的中文主题；必须与文件名中日期后的主题完全一致。
- `date`：草稿在 `Asia/Shanghai` 的创建日，必须是真实日历日期并与文件名日期一致；创建后冻结，跨日修改或发布不改变。
- `submitter`：非空单行提交人；优先取 `git config user.name`，缺失时询问用户。
- `topics`：一至三个非空主题，与包内独立微型 lesson 对应。

文件名固定为 `yyyy-MM-dd-{中文主题}.md`。主题必须是以中文表达核心语义的短语；可以嵌入标准技术术语或数字，但去除这些嵌入内容后，剩余中文仍须表达可识别的主题含义。任意英文串仅附加一个汉字不构成中文短语。主题还必须具体表达可复用知识，禁止使用“技术总结”“开发记录”等宽泛标签。

按以下顺序规范化候选主题，字符范围不得自行扩大或缩小：

1. 将所有空白字符替换为 `-`。
2. 删除 `/`、`\\`、`:`、`*`、`?`、`"`、`<`、`>`、`|`、`#`、`%`、ASCII 控制字符 U+0000–U+001F 和 U+007F。
3. 将连续的 `-` 合并为一个 `-`。
4. 删除首尾的 `-`。

规范化结果同时用于 frontmatter `title` 和文件名主题，且不得为空。

## 草稿完成标准

草稿仅在以下检查全部通过后完成：必要主题条件成立；两项建议性成熟度信号已经评估，且缺失项已明确标注状态、证据边界与待验证事项；主题数为一至三个且逐个独立完成 Bug/Knowledge 分类；正文使用对应标题、顺序及省略规则；UTF-8 Markdown 文件名匹配 `YYYY-MM-DD-TOPIC.md`，且主题通过中文短语语义与精确规范化检查；frontmatter 以独立的 `---` 行开始和结束，只含 `title`、`date`、`submitter`、`topics`，其中标题与文件名主题完全一致、日期真实且与文件名一致、提交人为非空单行、topics 含一至三个非空值。publisher 的 `validate_document` 检查上述文件格式、至少一个 CJK 统一表意文字和 frontmatter 一致性；中文短语语义由草稿门额外检查，不能以“含一个汉字”替代。
