# Codemao Learning

按以下六门顺序处理当前 Codex 对话；每一门通过前都停留在该门。

## 资格门

完整读取 `references/resolution-contract.md` 后再判断。只使用当前 Codex 对话和当前工作区；能从代码、diff、测试或项目文档发现的证据直接检查，不向用户询问。仅在机制依据确有需要时浏览官方文档或其他一手资料。

确认存在符合契约教学目标的高价值、可迁移主题，并评估“问题或任务是否已解决”“方案是否已验证有效”两项建议性成熟度信号。任一成熟度信号缺失时继续生成，但必须在草稿中明确当前状态、证据边界与待验证事项，不得把候选结论写成已验证事实。仅当不存在高价值、可迁移且非简单机械修改的主题时，说明依据，不创建 Markdown，立即结束。

**完成标准：** 至少一个高价值、可迁移且非简单机械修改的主题已由证据确认；两项建议性成熟度信号均已评估，缺失项已有明确披露。未通过不得进入草稿门。

## 草稿门

完整读取 `references/teaching-contract.md` 后再起草，同时继续以 `references/resolution-contract.md` 为格式、分类和结构的单一事实源。

运行 `git config user.name` 确定提交人；仅在结果缺失时询问。按 `Asia/Shanghai` 的创建日期，在独立临时目录创建一份 UTF-8 Markdown 学习包，包含一至三个独立主题，并严格满足两个契约。创建后冻结日期。

分别执行两个契约的完成检查。只有全部通过后，才向用户展示完整 Markdown 和临时路径。

**完成标准：** 当前草稿同时通过知识提取、学习包格式与教学完成标准，且完整内容及临时路径已展示。未通过不得进入内容门。

## 内容门

询问当前草稿是否准确、满意。

用户指出不准确之处时，直接按其反馈修订，不重新核验；重新展示完整草稿并重复内容门。用户认为不准确但拒绝指出具体问题时，警告仍有未解决的不准确内容，并要求其明确选择继续或取消；选择继续只通过本门，不构成发布授权。

**完成标准：** 用户明确表示满意，或在收到风险警告后明确选择继续；当前完整草稿已展示。未通过不得进入安全门。

## 安全门

扫描最终草稿。删除密钥、令牌、密码、Cookie、私钥等凭证，且永不发布其原始形式；个人、客户和生产数据默认脱敏；对含义或敏感性不明确的内部标识询问用户。

任何安全处理导致内容变化时，展示修改后的完整草稿并返回内容门。

**完成标准：** 当前展示的确切版本不存在未解决、会阻止发布的敏感数据。未通过不得进入发布门。

## 发布门

针对通过安全门的准确版本，单独询问用户是否明确授权发布。此前的“满意”“继续”或其他确认均不授权发布。

授权前不得读取 GitLab 配置，不得克隆、提交或推送。

**完成标准：** 用户已明确授权发布当前安全版本。未通过不得进入完成门。

## 完成门

获得授权后，读取 `references/gitlab-target.json`；运行 `python3 scripts/publish.py --help` 获取发布器参数与行为，再以最终草稿和提交人调用发布器。

若发生语义冲突，根据正文生成更具体的中文主题，同时更新文件名和 frontmatter `title` 后自动重试，最多三次。三次仍冲突时，询问用户开始新一组三次尝试还是取消。

发布器报错时，报告原始错误消息和保留的草稿路径；不得改用分支、Merge Request 或强制推送。

**完成标准：** 仅当发布器退出 0，并返回状态、目标路径和 commit 时通过；报告这三项。退出 3 继续冲突处理，任何其他结果均未完成。
