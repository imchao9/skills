# 默认篮球比赛交付提示词

复制下面的提示词，只替换比赛链接和百度网盘根目录。

```text
请使用 $basketball-video-delivery 处理以下小球迷篮球比赛：

比赛链接：
- <比赛链接1>
- <比赛链接2>

百度网盘根目录：<例如 /篮球/Alpha球会>

默认交付包（每场必须全部完成）：
1. 纯享版
2. 个人集锦（每位有有效事件的球员一条）
3. 全场集锦（双方交错、按比赛顺序、8–10分钟、数据标注版、1920×1080）
4. 球评海报（完整球评 Markdown、自包含 HTML、1080px 宽 PNG）

执行方式：
- 直接运行 `run_standard_delivery.py`，不要先逐条组织命令。第一次运行准备全部草稿并生成 `ai-review.json`；集中完成一次 AI 审核后，运行报告中的 `resume_command` 自动完成最终渲染、完整解码、交付校验和百度网盘同步。
- AI 不得为了继续流程直接勾选通过；必须实际检查审核文件列出的纯享代理、异常事件、数据标注版全场集锦及接触表、球评 HTML 和 PNG。
- 最终1080p产物生成后，读取 `final-visual-review.json`。查看接缝前后帧并播放轻量接缝审核视频，只审核标记为 `required` 的项目：通常是纯享版剪切接缝；全场集锦和海报只有在主审核后变化时才复核。检查通过后再续跑上传。
- 下载和上传走正常网络，不挂代理。
- 编辑只使用完整回放作为视频源；优先用接口事件元数据、缩略图和计分牌 OCR 定位。只有无法可靠定位时，才下载平台事件短片作为对齐参考。
- 多场比赛保持 WIP=1：先完成一场的剪辑、验收、上传和远端核对，清理可重建的大型中间文件，再处理下一场。
- 复用通过验证的本地文件；不要重复下载、转码、上传或重新分析。

AI 只处理以下环节：
- 纯享版删除边界的视觉确认；
- 高风险事件匹配和重叠回合复核；
- 全场集锦的选片、去重和观感验收；
- 球评叙事与最终数据审校。

质量要求：
- 每个视频先 ffprobe，再完整解码；全场集锦必须覆盖双方和全部比赛时段。
- 全场集锦使用官方球员数据标注；不要把事件累计数写成官方全场数据。
- 球评所有数据以 match.json 为准。正文统一使用“出手在前、命中在后”，例如“78投19中”；表格使用 19/78 时必须标明“命中/出手”。
- HTML 先生成，再用真实浏览器检查排版并导出 PNG；优先使用用户提供的球队合照。
- 上传前运行标准交付包校验；缺少任一默认产物时不得报告完成。
- 百度网盘中：纯享版和球评放比赛根目录，个人集锦放“个人精彩集锦/”，全场集锦放“比赛精彩集锦/”。
- 上传后必须核对每个远端路径和精确字节数。只有四项产物全部通过本地及远端验证，才能结束。

最终只汇报：
- 每场四项产物的本地路径、数量、时长和分辨率；
- 百度网盘目标路径与远端验证结果；
- 清理了哪些可重建中间文件；
- 失败或跳过项及精确续跑命令。
```
