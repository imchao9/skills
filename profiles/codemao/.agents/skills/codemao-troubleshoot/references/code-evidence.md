# 代码证据

代码证据用于确认运行时路径、入口、调用链、配置读取方式，以及部署分支和当前本地代码是否匹配。

## 何时读取

用户提供仓库、类名、接口路径、服务名、配置 key、调用链线索，或需要解释日志、配置和数据为什么会这样时读取。

## 先用这条

先确认仓库路径、目标环境和当前分支：

```bash
git -C /path/to/repo branch --show-current
git -C /path/to/repo status --short
```

没有用户提供的仓库路径时，只检查当前明确可访问的工作区，不猜个人目录。

## Gotchas

- 代码证据解释“为什么可能发生”，运行时证据确认“是否真的发生”。

## 仓库选择

优先使用当前工作区、用户提供的仓库路径，或已经明确配置的仓库路径。

## 分支

| 环境 | 期望分支 |
| --- | --- |
| `prod` | `master` |
| `staging` | `master` |
| `test` | `test` |
| `press` | 用户提供；缺失时可先假设 `test`，但必须标注不确定性 |

如果本地分支和期望分支不一致，应强烈建议切换分支，并在切换前征得用户确认。

如果用户不同意切换，或当前无法切换，代码证据必须降级。不要基于不匹配分支的代码给强结论。

## 跨仓库问题

跨项目问题需要用户提供每个相关仓库路径，或只检查当前明确可访问的工作区。

能拿到日志、配置或数据证据时，应把代码证据和这些证据组合使用。代码可以解释“为什么会这样”，运行时证据用于确认“是否真的发生”。
