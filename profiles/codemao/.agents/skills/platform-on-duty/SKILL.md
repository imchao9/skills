# 平台值班峰值回填

把一次调用视为“查询并直接回填”的授权。使用 [`config.toml`](config.toml) 作为业务配置的单一事实来源。

## 固定规则

- 要求用户提供值班人；缺失时停止并询问，不查询、不写表。
- 日期支持 `今天`、`昨天`、`YYYY-MM-DD`；默认今天。
- 时间段默认 `18:30:00–20:00:00`，允许用户覆盖，但不允许跨天。
- 使用 `Asia/Shanghai`。开始时间尚未到时停止；开始时间已到但结束时间未到时，以当前时间为实际结束时间。
- 复用一个 SLS 标签页，不并发查询服务。用结果状态驱动等待，不使用固定时长休眠。
- 浏览器操作默认直接使用本地 Chrome 的现有登录态；禁止自动选择浏览器或先打开 Codex 应用内浏览器。Chrome 不可用时停止并报告，除非用户明确要求再改用其他浏览器。
- 正常路径按阶段批处理：一个稳定阶段只发起一次浏览器调用，在调用内部循环处理全部项目并逐项捕获失败；禁止因为单项失败抛弃整批成功结果。
- 浏览器操作优先走已验证的快速路径；只有快速路径出现明确失败时才进入局部诊断，禁止在正常路径中探索按钮、扫描整页 DOM 或生成中间截图。
- 查询、文字回填、SLS 截图、Grafana 截图和图片上传彼此独立：哪个成功就写哪个，失败项留空并报告。
- 所有服务查询都失败，或所有指标表头都无法唯一匹配时，不新增表格行。
- 接受 SLS 返回的精确或不精确结果；不精确时照常回填并在报告中标记。
- 截图必须使用 SLS 查询结果区域顶部的绿色时间柱状图，以及鼠标悬停后出现的黑色提示框；禁止打开、切换或配置下方“预览图表”的图表类型。
- 截图成功以最终候选图片字节的成品验收为准；页面 DOM 悬浮框正确不等于截图成功。禁止用结果表或无悬浮框图表降级代替。
- 候选截图只在内存中验收，不展示、不落盘；不逐格读回文字，只保留必要的写前保护、截图成品验收和最终保存校验。
- 不读取或保存 Cookie、AccessKey、临时签名和登录凭证。

## 1. 规范化本次运行

从用户话语中提取值班人、日期、开始时间、结束时间。只把明确提供的字段作为脚本参数；其余使用配置默认值。

运行：

```bash
python3 <skill-dir>/scripts/prepare_run.py \
  --attendant "林纬达" \
  --date "今天" \
  --start "18:30:00" \
  --end "20:00:00"
```

可省略 `--date`、`--start`、`--end`，不可省略 `--attendant`。脚本失败时把结构化错误翻译成中文告诉用户并停止。

完成标准：脚本返回 JSON，且其中的 `actual_start`、`actual_end`、`start_epoch`、`end_epoch`、每个服务的 `query_url` 和 `grafana.query_url` 都存在。

## 2. 准备读取与写入能力

1. 在一次浏览器调用中选择本地 Chrome 的 extension/CDP 实例、读取现有标签页，并按完整 URL 或标题接管 SLS、Sheet1、Grafana 标签页；缺少时才新建。不要调用自动浏览器选择，不要创建或接管 Codex 应用内浏览器标签页。
2. 最多保留三个受控标签页：SLS 只保留一个查询标签页；让 Sheet1 和 Grafana 在另外两个标签页后台加载，不等待它们完成再开始 SLS 查询。
3. 首次控制前完整读取 [`references/browser-fallback.md`](references/browser-fallback.md)、[`references/sls-fast-path.md`](references/sls-fast-path.md)、[`references/screenshot-capture.md`](references/screenshot-capture.md) 和 [`references/grafana-capture.md`](references/grafana-capture.md)；同次运行各读一次。
4. 本地 Chrome 无法连接时停止并告诉用户，不自动切换浏览器。登录失效、验证码或权限不足时，按对应服务或 Grafana 记录失败；连接重置或标签页接管超时时，按截图参考中的恢复规则处理。不要尝试读取浏览器凭证。

完成标准：已接管本地 Chrome，并获得 SLS、Sheet1、Grafana 三个可用标签页。

## 3. 查询峰值并生成截图

按 `prepare_run.py` 返回的服务顺序，在同一 SLS 标签页分两个批次完成：

1. 第一次浏览器调用按 SLS 快速路径循环全部服务，逐项完成“打开 `query_url` → 等待查询文本、实际时间范围和最终结果状态 → 读取结果表”。每个服务使用独立 `try/catch` 返回状态；单项失败不得终止循环。正常路径不等待 `networkidle`，不定位“查询/分析”按钮，不扫描整页 DOM。
2. 从已知结果表结构解析 `peak_second` 和 `request_count`。第一行是最大值，继续收集所有次数相同的并列峰值，并按秒升序保存。
3. 如果返回行数等于当前 `limit`，并且最后一行仍与第一行并列，把 `limit` 扩大 10 倍后重新生成该服务 URL 并查询；最大不超过配置的 `max_tie_limit`。达到上限仍无法证明并列完整时，保留已返回结果并在报告中标记。
4. 查询成功但没有任何日志时，把该服务结果记为字符串 `0`。
5. 页面加载、网络或超时错误最多重试 `retry_count` 次；语法、登录、权限错误不盲目重试。
6. 页面标记“结果不精确”时照常接受，并保存精度标记。
7. 对全部 `success` 服务选择最早的并列峰值，批量运行：

```bash
python3 <skill-dir>/scripts/prepare_screenshot.py \
  --service "auth-service" \
  --peak-epoch 1784779270 \
  --request-count 19000
```

8. 第二次浏览器调用按截图快速路径循环全部 `success` 服务，逐项完成“打开脚本返回的 `query_url` → 等待整分钟查询完成 → 定位顶部绿色图表 → 悬停并校验黑色提示框 → 整屏截图 → 内存裁剪”。逐项捕获失败，调用结束时一次性返回全部候选图片和状态。
9. 不进入下方“预览图表”，不点击“展开配置”，不设置横轴、纵轴或图表类型。整分钟查询完成后，直接使用查询结果区域顶部的绿色时间柱状图；确认它的时间轴覆盖 `minute_start–minute_end`，每个桶代表 1 秒。
10. 按截图参考，用 `peak_offset_seconds` 在顶部绿色时间柱状图的连续 60 秒时间轴上定位峰值柱。只读取该绿色图表的黑色悬浮框，要求“起始时间”和“次数”分别等于 `expected_tooltip.time` 与 `expected_tooltip.count`；不得读取下方预览图表的悬浮框，也不得通过翻页结果表推算柱序号。
11. 把“悬停并校验 DOM → 立即整屏截图”作为一次连续捕获；两者之间禁止执行会改变鼠标、焦点、滚动位置或悬浮状态的浏览器操作。禁止先尝试局部截图；整屏截图完成后再在内存中裁剪。
12. 一次性检查全部候选图片字节，要求图内可读地出现查询栏、分钟时间范围、精度状态、顶部绿色秒级柱状图，以及与 `expected_tooltip` 完全一致且未被裁切的黑色悬浮框。只对未通过验收的图片再发起一次批量重试调用；成功图片不重做。达到 `capture_retry_count` 后记录对应失败。

完成标准：每个服务只有 `success`、`zero` 或 `failed` 一种峰值状态；每个 `success` 服务另有“截图成功”或“截图失败”状态。只有最终候选图片本身通过全部成品验收项时，截图状态才是成功。

## 4. 生成 Grafana 资源曲线截图

1. 在一次浏览器调用中使用运行计划的 `grafana.query_url` 完成等待、定位、整页截图和内存裁剪；其中绝对时间范围必须等于本次 `actual_start–actual_end`，不要使用页面原有的 `now-1h–now`。
2. 按 Grafana 截图快速路径，只截取标题为“微服务与Pod资源曲线图”的整行，以及其中六个 CPU/内存资源曲线面板。
3. 直接检查候选图片字节；标题、六个面板、时间轴和图形区域全部通过成品验收后，才标记截图成功。
4. Grafana 截图失败不影响 SLS 查询、文字或其他图片回填；保留失败原因并继续。

完成标准：Grafana 只有“截图成功”或“截图失败”一种状态，成功时图片已经通过 [`references/grafana-capture.md`](references/grafana-capture.md) 的全部成品验收项。

## 5. 定位 Sheet1 的目标

只读取 `sheet.name` 指定的 `Sheet1`，不读取或修改其他工作表。

1. 把 Sheet1 定位与写前保护作为一次只读浏览器调用：执行 `Ctrl+Home`，一次复制并读取覆盖业务列和全部计划截图列的第一行表头；禁止点击或编辑名称框，禁止使用 `Ctrl+G`，不为表头定位生成验证截图。
2. 按配置中的 `header_keyword` 匹配指标列：忽略大小写、空格、连字符和下划线；每个关键字必须唯一匹配一列。
3. 精确匹配 `sheet.date_header`、`sheet.attendant_header` 和 `sheet.screenshot_start_header`。
4. 从日期列找到最后一个非空单元格；目标行是其下一行。忽略中间空洞，不回填历史空行。
5. 截图列从“服务监控情况”所在列开始：按服务配置顺序连续分配 SLS 截图，Grafana 截图固定顺延到所有服务截图之后。当前四个服务对应 J、K、L、M，Grafana 对应 N。
6. 只验证一次目标行的计划写入单元格均为空；不使用“从物理底部向上定位”的策略。

完成标准：一次只读调用返回目标行号、日期列、值班人列、至少一个指标列、全部截图目标列和目标行为空的结论。

## 6. 回填成功内容

先在内存构造完整文字行，再用一次浏览器调用完成全部写入与最终验收：

- 日期列：写 `YYYY-MM-DD`。
- 值班人列：写用户提供的原文。
- 指标列：写 `YYYY-MM-DD HH:mm:ss N次`；并列峰值在同一单元格内换行；零请求写 `0`；失败项留空。
- 在本地 Chrome 中一次粘贴连续文字区域，不逐格读回。
- 截图列：先按服务顺序写入通过成品验收的 SLS 截图，再把通过验收的 Grafana 截图写入下一列；必须使用内存图片剪贴板粘贴为单元格图片，不使用文件选择器或自由浮动图片。
- 把新增行行高调整为配置的 `image_row_height`；不要修改整表列宽。
- 等待页面显示“已保存”，并在同一次调用结束前返回一张只用于最终验收的表格截图。

所有服务都查询失败，或所有指标表头都无法匹配时，禁止新增行。单项写入出现明确失败时按配置重试；仍失败则保留其他成功内容。

检查这张最终截图，确认仍在 Sheet1、目标行可见、计划图片单元格显示缩略图、页面显示“已保存”。不再发起额外浏览器调用逐格读回文字或逐张生成验证截图。

完成标准：目标行之外没有修改；最终验收通过，或失败项已准确记录。

## 7. 收尾报告

报告：

- 实际查询时间段；
- 新增的 Sheet1 行号；未新增时说明原因；
- 每个服务的全部峰值时间和次数；
- SLS 结果是否标记为不精确；
- 文字、各服务 SLS 截图和 Grafana 资源曲线截图是否写入；
- 重试后仍失败的服务、列和原因。

用一次最终浏览器调用关闭 SLS 和 Grafana 标签页、保留回填完成的钉钉表格和用户原有标签页，并释放浏览器控制。截图只在内存中流转，无需清理临时文件。

完成标准：报告能逐项对应配置中的每个服务，且正常无重试路径只包含七次浏览器调用：标签页准备、批量峰值查询、批量 SLS 截图、Grafana 截图、表格写前检查、表格写入与最终验收、浏览器收尾。
