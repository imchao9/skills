# Grafana 资源曲线截图

使用本地 Chrome 生成 Grafana 截图时完整执行本文件。截图时间和目标区域都由运行计划决定，不使用页面默认的相对时间。

## 快速路径

1. 在一次浏览器调用中打开运行计划的 `grafana.query_url`，并在调用结束前完成等待、定位、整页截图和内存裁剪。URL 的 `from`、`to` 必须分别等于 `grafana.start_epoch_ms`、`grafana.end_epoch_ms`；保留配置中的 Namespace、Container、Pod 等变量及重复的 `var-Container` 参数。
2. 等待标题为 `grafana.section_title` 的行，以及下列六个面板完成渲染：
   - `微服务(容器名)整体CPU使用率(最大100%)`
   - `微服务(容器名)整体内存使用率`
   - `微服务(容器名)整体内存使用量`
   - `Pod容器CPU使用率(可关联节点)`
   - `Pod容器内存使用率(可关联节点)`
   - `Pod容器内存使用量(可关联节点)`
3. 如果目标行折叠，只点击该行标题展开一次；不要修改变量、刷新频率、面板配置或时间范围。
4. 只在目标行及六个已知面板的局部 DOM 中定位边界。滚动使面板完成懒加载后，截取整页或当前视口，再按“标题 + 六个面板”的联合边界在内存中裁剪；不创建临时图片文件。
5. 面板显示加载中、错误或 `No data` 时等待最终状态。页面、网络或超时错误按 `grafana.capture_retry_count` 有界重试；登录、验证码或权限错误直接记录失败。

完成标准：候选图片的时间范围来自本次运行计划，且裁剪区域只覆盖目标标题和六个资源曲线面板。

## 成品验收

把候选图片字节送入当前视觉检查通道，逐项确认：

- 可读地出现 `微服务与Pod资源曲线图`；
- 六个面板标题全部可读；
- 六个面板的图形区域均已完成渲染，没有加载遮罩、错误或 `No data`；
- 横轴时间落在本次 `actual_start–actual_end` 内；
- 图片未混入相邻的其他 Grafana 行，六个面板边缘没有被裁切。

任一项失败都丢弃候选图，从快速路径第 2 步重新获取边界并截图，最多重试 `grafana.capture_retry_count` 次。只有通过全部验收项的图片才标记为 `grafana_capture_status = validated`。

完成标准：得到一张通过成品验收的 Grafana 截图，或准确记录失败原因。
