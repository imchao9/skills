# SLS 秒级截图捕获

SLS 使用 Chrome 时完整执行本文件。候选图片字节是截图结果的唯一验收对象；DOM 只用于截取前定位，不能证明最终图片合格。

## 绿色图表快速路径

只发起一次浏览器调用，在调用内部复用截图函数并循环全部 `success` 服务。每个服务在独立 `try/catch` 中完成导航、定位、悬停、校验、截图和裁剪：

1. 打开整分钟截图 URL，等待查询文本、分钟时间范围、精度状态和顶部绿色时间柱状图同时出现。
2. 目标图表固定为查询结果区域顶部、位于“日志条数/统计分析”信息下方且位于“原始日志/统计图表”标签上方的绿色时间柱状图。禁止点击“展开配置”，禁止选择下方“预览图表”的任何图表类型。
3. 确认绿色图表时间轴覆盖 `minute_start–minute_end`，每个桶代表 1 秒。即使某秒没有请求，该秒仍占据固定位置；不得翻页结果表，也不得按非零数据点序号定位。
4. 令 `bucket_width = plot_width / 60`，目标横坐标为 `plot_left + (peak_offset_seconds + 0.5) * bucket_width`。优先命中该坐标；需要微调时只在相邻一个桶宽内做有界尝试。
5. 只接受绿色图表生成的黑色悬浮框。要求“起始时间”等于 `expected_tooltip.time`，“次数”等于 `expected_tooltip.count`；次数按数值比较，允许千分位逗号或空格。
6. 在该批量调用内完成悬停校验后，保持鼠标、焦点、滚动位置和标签页不变，立即截取当前视口。禁止把同一服务的悬停与截图拆到不同浏览器调用。
7. 截图后再对图片字节做内存裁剪。禁止先尝试 `clip` 局部截图，也不创建临时图片文件。
8. 保存当前服务的候选图片或明确失败原因后继续下一个服务；单项失败不得终止批量调用。调用结束时一次性返回全部候选图片和状态。

完成标准：目标柱位于顶部绿色秒级时间轴，黑色悬浮框的起始时间和次数与预期峰值完全一致。

## 有界重试

1. 黑色悬浮框未出现或内容不一致时，在预测坐标左右各不超过一个 `bucket_width` 的范围内微调，最多尝试 `hover_retry_count` 次。
2. 候选图未通过成品验收时，把所有失败项合并到一次重试调用，从快速路径第 4 步重新执行；成功项不重做，最多重试 `capture_retry_count` 次。
3. 只有绿色图表区域本身无法定位时，才局部检查“日志条数/统计分析”和“原始日志/统计图表”之间的图表容器；禁止枚举整页图表或切换下方预览图表。

完成标准：得到通过验收的候选图片，或在有限次数后准确记录截图失败。

## 成品验收

把批量返回的全部候选图片字节一次性送入当前视觉检查通道；这是内部成品验收，不向用户展示，也不写临时文件。逐项确认图片本身可读地包含：

- 当前服务的查询条件；
- 峰值所在整分钟的开始、结束时间；
- SLS 的精度状态；
- 顶部绿色秒级时间柱状图；
- 未被裁切的黑色悬浮框；
- 黑色悬浮框的起始时间等于 `expected_tooltip.time`；
- 悬浮框次数按数值等于 `expected_tooltip.count`，显示千分位不算差异。

任一项不可读、缺失、被遮挡或不一致，都丢弃该候选图；重新获取绘图区，从“绿色图表快速路径”第 4 步开始重做，最多重试 `capture_retry_count` 次。不要因为 DOM 曾经正确而放宽图片验收，也不要把失败候选图交给回填步骤。

完成标准：全部七项在同一张候选图片中通过，记录 `capture_status = validated`；否则记录截图失败。

## 浏览器断连恢复

浏览器连接重置或标签页接管超时时：

1. 保留已经确认的峰值时间、次数和截图计划；丢弃未通过成品验收的候选图以及旧标签页句柄。
2. 对原标签页最多重新接管一次；失败后立即从配置 URL 打开新的受控标签页，不反复接管旧标签页。
3. SLS 新标签页只重新运行当前服务的整分钟截图查询；已确认的整段峰值查询不重跑。
4. 钉钉新标签页重新确认 `Sheet1`、表头映射、目标行和计划单元格为空后才继续写入；不得凭旧句柄状态直接写入，也不得新增第二行。
5. 登录失效、验证码或权限错误不按断连处理，直接记录对应失败。

完成标准：恢复后从最近的安全检查点继续，没有重复查询已确认峰值，没有重复新增表格行。
