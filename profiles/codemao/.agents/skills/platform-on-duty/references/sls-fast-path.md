# SLS Chrome 查询快速路径

使用本地 Chrome 查询 SLS 时读取并执行本文件。正常路径只使用这里定义的已知结果状态和结构；页面结构明确失效时才进入失败分支。

## 正常路径

只发起一次浏览器调用，在调用内部复用查询函数并按配置顺序循环全部服务。每个服务在独立 `try/catch` 中完成：

1. 打开服务的 `query_url`。
2. 等待以下三个条件同时成立：
   - 查询容器 `[class*="BaseSearch-m__query-container__"]` 包含该服务的检索条件；
   - 页面出现“结果精确”或“结果不精确”；
   - `[class*="table-m__table-wrap__"]` 可见，或页面明确显示结果行为 0。
3. 从 `[class*="table-m__table-wrap__"]` 内的 `.obviz-base-easyTable-body .obviz-base-easyTable-row` 顺序读取结果，只解析 `peak_second` 和 `request_count`。
4. 同时保存精度状态、结果行数和查询文本校验结果，追加到批量结果后立即处理下一个服务；禁止单项异常终止整个调用。

禁止在正常路径中：

- 等待 `networkidle`；
- 查找或点击“查询/分析”按钮；
- 枚举页面所有按钮、输入框、表格或图表；
- 获取整页 DOM snapshot；
- 为识别页面结构生成截图；
- 为单个服务或同一个稳定状态拆出额外浏览器往返。

完成标准：一次浏览器调用返回与配置服务数量相同的结果数组；每项都有查询校验、精度、结果行数、峰值行或明确失败原因。

## 失败分支

只有正常路径的已知选择器超时或返回结构不完整时执行：

1. 在同一次批量调用内部重新加载当前服务 URL 一次，并重新运行该服务的正常路径。
2. 仍失败时，只检查查询容器、精度状态区域和结果表三个局部区域；禁止扩大为整页扫描。
3. 找到兼容选择器后，在内存中更新本次运行的复用查询函数，只批量重试失败服务；成功服务不重查。
4. 页面加载、网络或超时错误按 `retry_count` 处理；语法、登录和权限错误直接记录失败。

完成标准：恢复到正常路径，或当前服务被准确记录为失败；不会反复探索同一页面结构。
